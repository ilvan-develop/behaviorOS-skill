# P1.2 — Audit Governance

>behaviorOS v1.1.0 · Planejamento de implementação
>Data: 2026-08-18 · Estado: PLANNED

## Objetivo

Transformar o audit trail de ficheiro de debug em componente governado do kernel, separando a **fonte de decisão** (governance state) da **fonte de explicação** (audit trail).

## Arquitectura alvo

```
tool.execute.before
        │
        ├──→ governance-state.json   ← SOURCE OF DECISION
        │         │
        │         ├── event
        │         ├── timestamp
        │         ├── sessionID
        │         ├── expiresAt
        │         └── TTL
        │         │
        │         ↓
        │    Gate Decision
        │         │
        │    ┌────┴────┐
        │    ↓         ↓
        │  ALLOW      DENY
        │    │         │
        │    └────┬────┘
        │         ↓
        └──→ audit.jsonl            ← SOURCE OF EXPLANATION
                  │
                  ├── evento registado
                  ├── rationale
                  └── contexto
```

## Fase 0 — Contract & Invariants

### 0.1 Schema: governance-state.json


```json
{

  "event": "context7_queried",
  "timestamp": "2026-08-18T10:30:00.000Z",
```

### 0.3 Invariantes

| ID | Invariant | Descrição |
|----|-----------|-----------|
| I-01 | TTL obrigatório | Cada entrada DEVE ter `expiresAt` calculado a partir de `ttlMinutes[gate]` |
| I-02 | Sessão associada | Cada entrada DEVE ter `sessionID` válido |
| I-03 | Sem expiração | Estado expirado NUNCA resulta em ALLOW — lido como ausência |
| I-04 | Escrita atómica | Atualizações usam write-to-temp + rename (ou writeFileSync atómico) |
| I-05 | Schema versionado | `schemaVersion` no topo; incompatível → descartar, não migrar |
| I-06 | Fail-closed | Estado inválido, corrompido ou ausente → DENY para gates que o requerem |
| I-07 | Audit de atualização | Toda escrita ao governance state gera evento correspondente no audit trail |
| I-08 | Não substituir audit | Corrupção do audit trail NÃO substitui o governance state como fonte de decisão |
| I-09 | Max entries | `maxEntries` impede crescimento indefinido — LRU eviction |
| I-10 | Append-only semantics | Entradas são appendadas, nunca editadas in-place |

### 0.4 Semântica de corrupção

| Cenário | Comportamento | Estado |
|---------|---------------|--------|
| State inválido (JSON parse fail) | Recriar vazio; todos os gates que dependem de state → DENY | `STATE_CORRUPTED` |
| State de outro projecto | Descartar; projectId mismatch = estado novo | `STATE_CORRUPTED` |
| State de schema incompatível | Descartar; schemaVersion mismatch = estado novo | `STATE_CORRUPTED` |
| Audit inválido (JSON parse fail) | Não substituir state; manter último state válido | `MISSING_AUDIT` |
| Audit truncado | Ler até onde é válido; ignorar linhas corrompidas | `DEGRADED` |
| Mismatch state/audit | State diz "context7 queried" mas audit não tem registro | `DEGRADED` |
| State ausente | Criar novo; gates que dependem → DENY até nova evidência | `MISSING_AUDIT` |
| Ambos ausentes | Criar ambos; enforcement funciona com base em policy apenas | `MISSING_AUDIT` |

### 0.6 Decisões de design

**Q: Por que não usar audit trail como source of decision?**
R: O audit trail é append-only, cresce indefinadamente, e a leitura é O(n). Usar como source de decisão cria dependência de performance e integridade num componente que não foi desenhado para isso.

**Q: Por que TTL em vez de event count?**
R: TTL é semantically mais claro: "context7 query é válida por 30 minutos". Event count ("últimas 50 queries") não captura a degradação temporal — uma query de 2 horas atrás não deveria satisfazer um gate hoje.

**Q: Por que fail-closed em vez de fail-open?**
R: Fail-open significaria que corrupção de estado permite qualquer operação. Fail-closed é mais conservador — bloqueia até que evidência válida seja fornecida. O custo é um false deny temporário; o benefício é zero bypass.

```javascript
function getValidEntry(root, gate, sessionID) {
  const state = readState(root);
  if (!state) return null;  // fail-closed

  const now = Date.now();
  const entry = state.entries.find(e =>
    e.gate === gate &&
    e.sessionID === sessionID &&
    new Date(e.expiresAt).getTime() > now
  );

  return entry || null;  // expirado = ausência
}
```

### 1.3 Escrita atómica

```javascript
function writeState(root, state) {
  const path = join(auditDir(root), 'governance-state.json');
  const tmp = `${path}.tmp.${process.pid}`;

  // 1. Escrever para temp
  writeFileSync(tmp, JSON.stringify(state, null, 2));

  // 2. Validar o que foi escrito
  const parsed = JSON.parse(readFileSync(tmp, 'utf8'));
  const { valid } = validateState(parsed);
  if (!valid) {
    unlinkSync(tmp);
    throw new Error(`State validation failed: ${valid}`);
  }

  // 3. Rename atómico
  renameSync(tmp, path);
}
```

### 2.3 Decisão de rotação

Rotação dispara quando QUALQUER uma das condições é verdadeira:

| Condição | Threshold | Default |
|----------|-----------|---------|
| Tamanho do ficheiro | `maxSizeKB` | 100KB |
| Número de eventos | `maxEvents` | 1000 |
| Idade do mais antigo | `maxAgeDays` | 365 |

```javascript
function shouldRotate(root) {
  const cfg = loadGovernanceJSON(root, 'audit.json');
  const currentPath = join(auditDir(root), 'current.jsonl');

  if (!existsSync(currentPath)) return false;

  const stats = statSync(currentPath);

  // Size threshold
  if (stats.size > (cfg.retention?.maxSizeKB || 100) * 1024) return true;

  // Event count threshold
  const lineCount = countLines(currentPath);
  if (lineCount > (cfg.rotationThreshold?.maxEvents || 1000)) return true;

  // Age threshold
  const oldest = getOldestEvent(currentPath);
  if (oldest) {
    const ageDays = (Date.now() - oldest) / (1000 * 60 * 60 * 24);
    if (ageDays > (cfg.retention?.maxAgeDays || 365)) return true;
  }

  return false;
}
```

### 2.4 Rotação atómica

```javascript
function rotate(root) {
  const auditDirPath = auditDir(root);
  const currentPath = join(auditDirPath, 'current.jsonl');
  const now = new Date();
  const archiveDir = join(auditDirPath, 'archive',
    String(now.getFullYear()),
    String(now.getMonth() + 1).padStart(2, '0'));

  // 1. Criar directório de archive
  mkdirSync(archiveDir, { recursive: true });

  // 2. Gerar nome do archive
  const dateStr = now.toISOString().split('T')[0];
  const archivePath = join(archiveDir, `audit-${dateStr}.jsonl`);

  // 3. Se já existe archive para hoje, appendar
  if (existsSync(archivePath)) {
    appendFileSync(archivePath, readFileSync(currentPath));
  } else {
    renameSync(currentPath, archivePath);
  }

  // 4. Criar novo current.jsonl vazio
  writeFileSync(currentPath, '');
}
```

### 2.5 Políticas de retenção

```javascript
function enforceRetentionPolicy(root) {
  const cfg = loadGovernanceJSON(root, 'audit.json');
  const archiveDir = join(auditDir(root), 'archive');
  if (!existsSync(archiveDir)) return;

  const maxAgeDays = cfg.retention?.maxAgeDays || 365;
  const maxArchives = cfg.retention?.maxArchives || 100;
  const cutoff = Date.now() - maxAgeDays * 24 * 60 * 60 * 1000;

  // 1. Remover arquivos expirados
  for (const file of listArchiveFiles(archiveDir)) {
    if (file.mtime < cutoff) {
      unlinkSync(file.path);
    }
  }

  // 2. Remover directórios vazios
  cleanEmptyDirs(archiveDir);

  // 3. Limitar número total de arquivos
  const remaining = listArchiveFiles(archiveDir);
  if (remaining.length > maxArchives) {
    const toDelete = remaining
      .sort((a, b) => a.mtime - b.mtime)
      .slice(0, remaining.length - maxArchives);
    for (const file of toDelete) {
      unlinkSync(file.path);
    }
  }
}
```

### 2.6 appendAudit actualizado

```javascript
function appendAudit(root, entry) {
  const dir = auditDir(root);
  if (!existsSync(dir)) mkdirSync(dir, { recursive: true });

  const record = { timestamp: new Date().toISOString(), ...entry };
  const line = JSON.stringify(record) + '\n';

  // 1. Verificar se precisa de rotação
  if (shouldRotate(root)) {
    rotate(root);
  }

  // 2. Append atómico
  appendFileSync(join(dir, 'current.jsonl'), line);

  // 3. Executar retenção periodicamente (a cada 100 escritas)
  stateWriteCount = (stateWriteCount || 0) + 1;
  if (stateWriteCount % 100 === 0) {
    enforceRetentionPolicy(root);
  }

  return record;
}
```

## Fase 3 — Windowed Reader

### 3.1 Novo reader

```javascript
function readAuditWindow(root, {
  sessionID,
  eventType,
  since,           // Date | timestamp | ISO string
  limit = 100,
  includeArchive = false
} = {}) {
  const dir = auditDir(root);
  const files = [];

  // 1. Current file
  const currentPath = join(dir, 'current.jsonl');
  if (existsSync(currentPath)) {
    files.push(currentPath);
  }

  // 2. Archive files (se pedido)
  if (includeArchive) {
    const archiveDir = join(dir, 'archive');
    if (existsSync(archiveDir)) {
      files.push(...listArchiveFiles(archiveDir).map(f => f.path));
    }
  }

  const sinceMs = since ? new Date(since).getTime() : 0;
  const results = [];

  // 3. Ler do mais recente para o mais antigo
  for (const file of files.reverse()) {
    const lines = readLinesReverse(file);

    for (const line of lines) {
      try {
        const rec = JSON.parse(line);

        // Filtro temporal
        if (sinceMs && new Date(rec.timestamp).getTime() < sinceMs) {
          return results;  // Já passamos da janela
        }

        // Filtro por sessão
        if (sessionID && rec.sessionID && rec.sessionID !== sessionID) {
          continue;
        }

        // Filtro por evento
        if (eventType && rec.event !== eventType) {
          continue;
        }

        results.push(rec);

        if (results.length >= limit) return results;
      } catch {
        // Linha corrompida — ignorar
      }
    }
  }

  return results;
}
```

### 3.2 Leitura reversa eficiente

```javascript
function readLinesReverse(filePath) {
  // Ler os últimos N KB em vez do ficheiro inteiro
  const stats = statSync(filePath);
  const readSize = Math.min(stats.size, 50 * 1024); // 50KB max
  const buffer = Buffer.alloc(readSize);

  const fd = openSync(filePath, 'r');
  readSync(fd, buffer, 0, readSize, stats.size - readSize);
  closeSync(fd);

  return buffer.toString('utf8').split('\n').filter(Boolean).reverse();
}
```

### 3.3 readAuditEvents actualizado

```javascript
// Manter compatibilidade retroativa
function readAuditEvents(root, { event, windowMinutes = 30, sessionID } = {}) {
  const since = new Date(Date.now() - windowMinutes * 60 * 1000);
  return readAuditWindow(root, {
    sessionID,
    eventType: event,
    since,
    includeArchive: false

}
```

### 4.2 Estados de reconciliação

| Estado | Significado | Acção |
|--------|-------------|-------|
| `SYNCED` | State e audit estão alinhados | Nenhuma |
| `DEGRADED` | Mismatch entre state e audit | Warning; manter state como autoridade |
| `MISSING_AUDIT` | State existe mas audit não | Criar audit; manter state |
| `STATE_AHEAD` | State tem entrada sem audit correspondente | Registrar no audit; DEGRADED |
| `STATE_CORRUPTED` | State é inválido | Recriar vazio; todos os gates → DENY |
| `AUDIT_CORRUPTED` | Audit tem linhas inválidas | Ignorar linhas inválidas; DEGRADED |

### 4.3 Algoritmo de reconciliação

```javascript
function reconcileStateAudit(root) {
  const state = readState(root);
  const auditPath = join(auditDir(root), 'current.jsonl');

  // 1. Validar state
  if (!state || !validateState(state).valid) {
    return { status: 'STATE_CORRUPTED', details: 'State invalid or missing' };
  }

  // 2. Validar audit
  if (!existsSync(auditPath)) {
    return { status: 'MISSING_AUDIT', details: 'Audit file missing' };
  }

  // 3. Verificar sincronismo
  const stateEntries = state.entries || [];
  const auditEvents = readAuditWindow(root, {
    since: new Date(Date.now() - 60 * 60 * 1000), // 1 hora
    limit: 1000
  });

  const stateEventKeys = new Set(stateEntries.map(e => `${e.event}:${e.sessionID}`));
  const auditEventKeys = new Set(auditEvents.map(e => `${e.event}:${e.sessionID}`));

  // 4. StateAhead: state tem entrada que audit não tem
  for (const key of stateEventKeys) {
    if (!auditEventKeys.has(key)) {
      return {
        status: 'STATE_AHEAD',
        details: `State entry ${key} not found in audit`,
        recommendation: 'Register missing event in audit'
      };
    }
  }

  // 5. AuditAhead: audit tem evento que state não tem (normal — audit é superset)
  // Isto é normal: audit registra tudo, state mantém apenas o necessário para decisões

  return { status: 'SYNCED', details: 'State and audit are aligned' };
}
```

## Riscos

| Risco | Impacto | Mitigação |
|-------|---------|-----------|
| Breaking change no appendAudit | Alto | Manter assinatura; testes de retrocompatibilidade |
| Corrupção durante rotação | Alto | renameSync é atómico no POSIX; no Windows usar replaceFileSync |
| Performance do windowed reader | Médio | Cache de último offset; leitura reversa limitada a 50KB |
| governance-state.json cresce | Baixo | maxEntries + LRU eviction |

## Notas de implementação

1. **Windows compatibility:** `renameSync` não é atómico no Windows quando o destino já existe. Usar `replaceFileSync` (Node 20+) ou copy+delete como fallback.

2. **Concorrência:** `appendFileSync` é atómico para writes menores que PIPE_BUF (4096 bytes). Entradas de audit são tipicamente < 1KB. Para governance-state.json, usar write-to-temp + rename.

3. **Backward compatibility:** `readAuditEvents` mantém a assinatura actual. Internamente delega para `readAuditWindow`. Chamadores existentes não precisam de alterações.

4. **Testes:** Cada fase deve ter os seus testes antes de avançar para a próxima. A Fase 5 é a suite adversarial completa, mas testes unitários por fase devem existir desde a Fase 1.
