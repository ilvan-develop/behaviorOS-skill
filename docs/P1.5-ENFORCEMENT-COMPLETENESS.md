## 1. Context & Problem

The BehaviorOS governance kernel has proven 60 invariants across P1.2 (Audit), P1.3 (Truth), and P1.4 (Architecture). However, the governance contract declares 29 policies, of which 4 enforced, fail-closed policies have **no adversarial tests** proving the block actually fires.

This is the gap between "declared enforcement" and "proven enforcement."

### Problem Statement

```
DECLARED: version-pinning-gate.json → fail-closed
PROVEN:  No test fires this block

DECLARED: tool-gate.json → fail-closed
PROVEN:  No test fires this block

DECLARED: permissions-matrix.json → fail-closed
PROVEN:  No test fires this block

DECLARED: version-registry.json → fail-closed
PROVEN:  No test fires this block
```

P1.5 closes this gap by proving every declared enforcement chain actually works.

## 3. Invariants I-61 → I-70

### I-61: Enforcement completeness is provable

**Statement:** Every enforced, fail-closed policy must have an adversarial test proving the block fires.

**Source:** governance-contract.json (24 enforced policies)

**Verification:** All 24 enforced policies have non-empty `adversarialTests` arrays in the contract.

### I-62: Version pinning enforcement is active

**Statement:** If a dependency is not pinned to an exact version, the version-pinning-gate MUST block the operation.

**Source:** version-pinning-gate.json (kernel authority, fail-closed)

**Consumer:** oage-enforce.js

**Verification:** Adversarial test fires this block with an unpinned dependency.

### I-63: Tool gate enforcement is active

**Statement:** If a tool is not in the allowed tools list, the tool-gate MUST block the operation.

**Source:** tool-gate.json (kernel authority, fail-closed)

**Consumer:** oage-enforce.js, tool-guard.ps1

**Verification:** Adversarial test fires this block with a disallowed tool.

### I-64: Permissions matrix enforcement is active

**Statement:** If an agent attempts an action outside its allowed phases, the permissions-matrix MUST block the operation.

**Source:** permissions-matrix.json (handoff authority, fail-closed)

**Consumer:** permission-guard.ps1

**Verification:** Adversarial test fires this block with an out-of-scope phase.

### I-65: Version registry enforcement is active

**Statement:** If a dependency version does not match the registry, the version-registry MUST block the operation.

**Source:** version-registry.json (kernel authority, fail-closed)

**Consumer:** oage-enforce.js

**Verification:** Adversarial test fires this block with a mismatched version.

### I-66: Unenforced policies are explicitly declared

**Statement:** Any policy that has no consumer MUST be declared as unenforced in the governance contract with a documented rationale.

**Source:** governance-contract.json

**Verification:** All 5 unenforced policies have documented reasons.

### I-67: Declarative policies have no runtime enforcement

**Statement:** Policies with `"authority": "declarative"` MUST NOT be enforced at runtime.

**Source:** governance-contract.json

**Verification:** No runtime consumer applies these policies.

### I-68: Superseded policies remain disabled

**Statement:** Any policy that has been superseded by another MUST remain disabled and not be re-enabled.

**Source:** context7-gate.json (superseded by policy-resolver.json)

**Verification:** truth-gate.json and context7-gate.json remain disabled.

### I-69: Phase boundaries are enforced

**Statement:** State transitions (F0→F1→...→F7) MUST be validated against the state machine before execution.

**Source:** state-machine.json (kernel authority, fail-closed)

**Verification:** State machine validation is proven by the existing enforcement chain.

### I-70: Governance contract is the single source of policy truth

**Statement:** The governance contract must declare all enforced policies. No policy can be enforced without being declared in the contract.

**Source:** governance-contract.json

**Verification:** All 24 enforced policies are declared.

## 4. ADR-001: P1.5 Scope Definition

### Context

P1.5 addresses the gap between "declared enforcement" and "proven enforcement." The governance contract declares 24 enforced policies, but 4 of them have no adversarial tests.

### Decision

P1.5 will:

1. **Prove enforcement chains** for the 4 UNTESTED policies
2. **Resolve unenforced policies** (5 policies with no consumer)
3. **Verify enforcement completeness** across all 24 enforced policies

### Consequences

- All 24 enforced policies will have adversarial tests
- No more UNTESTED_POLICY warnings in the governance doctor
- P1.5 closes the enforcement gap completely
